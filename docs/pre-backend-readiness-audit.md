# تدقيق الجاهزية قبل بناء الخلفية

تاريخ التدقيق: 2026-09-08. هذا تدقيق للواجهة الحالية وبياناتها التجريبية، وليس ادعاءً بوجود خدمات خلفية.

| البند | الحالة | الدليل |
|---|---|---|
| مسارات التطبيق | مكتمل | جميع المسارات التطبيقية مبنية، مع صفحة دخول مستقلة. |
| البناء وفحص الأنواع | مكتمل | `npm run typecheck` و`npm run build` ناجحان. |
| واجهة عربية RTL والشعار | مكتمل | شعار `public/logo.png` والتنقل والتسميات بالعربية. |
| النطاقات الأساسية | مكتمل | مالك، عقار وموقعه، وحدة/شقة/دور، مستأجر، عقد إدارة، عقد إيجار وأقساط، استحقاق، دفعة، مصروف، تسوية وتحويل. |
| ملفات المالك/العقار/المستأجر | مكتمل | تبويبات عملية للبيانات والعقود والتحصيل والمصروفات والتسويات والمرفقات. |
| طلبات الصيانة | مكتمل للواجهة التجريبية | بيانات موحدة، تكلفة ومورد وأولوية، وقرار اعتماد/رفض تجريبي. |
| التذكيرات والإشعارات | مكتمل للواجهة التجريبية | قواعد تذكير، تذكيرات مجدولة، وحالة قراءة الإشعارات. |
| المستندات | مكتمل للواجهة | قوالب موحّدة، معاينة رسمية، Word بصيغة `.docx`، وطباعة المتصفح أو الحفظ كـPDF. |
| عكس الدفعات | مكتمل للبيانات التجريبية | يعيد مبلغ الدفعة للاستحقاق ويحافظ على سجل الدفعة بحالة ملغاة. |
| المرفقات | مكتمل لبيانات Mock | بيانات وصفية موحّدة تشمل الاسم والحجم والنوع والسجل المرتبط؛ لا يوجد تخزين دائم للبايتات قبل الخلفية. |
| الإضافة والتعديل | مكتمل لبيانات Mock | نافذة الإضافة المنبثقة ومسارات التعديل المباشرة تعدّل مصدر Mock الموحّد. |
| تصدير Word/PDF | مكتمل للعميل | Word مولد فعلياً في المتصفح، وPDF عبر نافذة طباعة المتصفح/حفظ كـPDF. |
| الصلاحيات والتدقيق | تصميم بيانات فقط | الأنواع موجودة، والتنفيذ الأمني يجب أن يكون في الخلفية. |

## علاقات البيانات التي تعتمد عليها الخلفية

```text
مالك ← عقارات ← وحدات/شقق/أدوار
مالك ← عقد إدارة ← خدمات/استثناءات/مرفقات
مستأجر ← عقد إيجار ← أقساط ← استحقاقات ← دفعات ← عكس دفعة
عقار/وحدة ← مصروفات وصيانة ← اعتماد مالك
تحصيلات − رسوم إدارة − مصروفات المالك = تسوية المالك ← تحويلات
```

## ما يجب عدم افتراضه عند بناء الخلفية

- لا تحفظ الواجهة بايتات الملفات بعد إعادة التحميل؛ مصدر الميتاداتا هو Mock فقط.
- لا تعتمد الخلفية على نصوص الواجهة أو معرفات العرض؛ استخدم العقود في `types/domain.ts` و`docs/api-handoff-map.md`.
- لا تنفذ الصلاحيات أو اعتماد الصيانة في الواجهة؛ يجب فرضها في API وقاعدة البيانات وسجل التدقيق.
- التصدير يعمل في العميل؛ عند الحاجة إلى أرشفة المستند أو توقيعه أو إرساله من الخلفية، يجب أن يتولى الـAPI عملية الإنشاء والتخزين.

## الأولوية المقترحة للـBackend

1. الهوية والصلاحيات وسجل التدقيق.
2. الملاك والعقارات والموقع والوحدات والمرفقات.
3. العقود (الإدارة والإيجار) وجدولة الأقساط والاستحقاقات.
4. الدفعات والعكس والمصروفات وتسويات وتحويلات الملاك ضمن معاملات ذرية.
5. الصيانة واعتمادات المالك والتذكيرات والإشعارات.
6. التقارير وتوليد المستندات والتصدير الفعلي.
