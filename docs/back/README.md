# حزمة بناء الخلفية وربط الواجهات

هذه المجلد هو المرجع التنفيذي الوحيد للباك‑إند. لا يبدأ فريق الواجهة صفحة جديدة، ولا يُستبدل Mock data في صفحة، قبل أن تنجح بوابة الإنهاء الخاصة بها في `04-delivery-gates.md`.

## ترتيب القراءة والتنفيذ

1. `01-data-model.md` — الكيانات والحقول والعلاقات وقواعد النزاهة.
2. `02-mysql-schema.sql` — DDL أولي لقاعدة MySQL 8.0.
3. `03-api-by-page.md` — كل مسار واجهة، بياناته وطلبات API وإجراءاته.
4. `04-delivery-gates.md` — معيار «لا ننتقل قبل الإنهاء» وخطة الربط.
5. `05-frontend-inventory.md` — جرد الحقول والإجراءات والتقارير كما تظهر في الواجهات.
6. `06-api-payload-contracts.md` — أمثلة طلبات/استجابات العمليات الحساسة.
7. `07-ui-api-binding.md` — عقد الربط التنفيذي لكل زر ومودال وإجراء وحالات النجاح والفشل وتحديث البيانات.

## القرارات الثابتة

- قاعدة البيانات MySQL 8.0+، المال `DECIMAL(18,2)`، وتواريخ الأعمال `DATE`، والأحداث `DATETIME(3)` بتوقيت UTC.
- كل مورد تابع لـ`organization_id`؛ لا يسمح إطلاقاً بربط معرف من مؤسسة أخرى.
- الدفعات والتسويات والتحويلات لا تُحذف؛ التصحيح يتم بالعكس/الإلغاء مع سبب وتدقيق.
- الخادم هو مصدر الحقيقة للأرصدة، حالة الاستحقاق، أتعاب الإدارة، وصافي تسوية المالك.
- كل عملية إنشاء/تأكيد مالية تستعمل `Idempotency-Key` وتعمل داخل معاملة DB.
- الاستجابة الموحدة: `{ data, meta? }`، وأخطاء الحقول `422`، والتعارضات المالية `409`.

## حدود الواجهة الحالية

الـMock موجود فقط إلى أن يكتمل المورد المقابل. عند ربط مورد بالـAPI، تستبدل الصفحة `mocks/data` و`services/quick-create` بعميل API وReact Query/SWR أو طبقة حالة مكافئة؛ لا تعمل الطريقتان معاً لنفس الصفحة.
